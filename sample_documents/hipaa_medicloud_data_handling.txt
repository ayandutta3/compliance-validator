MediCloud Storage Solutions — IT Security Architecture Document (2026)

MediCloud Storage Solutions provides cloud-based infrastructure for storing and managing
electronic health records on behalf of healthcare organizations. This document describes
our current data security architecture as of Q1 2026.

1. Data Encryption at Rest
   All databases containing patient health information are encrypted at rest using AES-256
   cryptographic standards. Encryption keys are managed by our in-house Key Management
   Service (KMS) and rotated every 90 days.

2. User Authentication and Access Logging
   System accounts require unique alphanumeric usernames and passwords assigned on a
   per-employee basis. Workstation terminals are configured with automatic session
   lock-out after 10 minutes of inactivity. Our access management platform captures
   all read, write, and delete transactions on patient database records.

3. Third-Party Cloud Storage Partnerships
   We store certain encrypted backup archives using Cloudcorp's public cloud
   infrastructure. We are currently in negotiations with Cloudcorp to finalize a
   formal data processing agreement. Despite ongoing negotiations, backup replication
   to Cloudcorp's environment has already been enabled, pending contract execution.

4. Network Transmission Standards
   All patient data transmitted across public networks uses SSL/TLS encryption.
   Our current production environment operates on TLS 1.2. An upgrade to TLS 1.3
   is scheduled as part of our next annual network refresh cycle.

5. Physical Facility Access Controls
   Server rooms housing patient database infrastructure are restricted to authorized
   personnel only. Access requires biometric palm-print authentication. A digital
   access registry automatically logs all visitor entries, and non-staff guests
   must be accompanied by a security escort at all times.
